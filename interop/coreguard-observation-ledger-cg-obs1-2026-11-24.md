## The rule this page exists to state

A verdict on a run is not one fact. It is a history of reads, and each read belongs to one observer at one time, over specific bytes. Collapsing that history into a single field on the run is how a 403 becomes a failed verification, how a read at 17:05 becomes evidence about 09:00, and how a caller inherits a verdict nobody can scope.

| Field | What it holds | Never substituted by |
|---|---|---|
| `observer` | who ran the check | the run's owner, or the verifier's host |
| `scope` | the access that observer held | a claim about what access exists |
| `observed_digest` | the bytes that observer recomputed | the digest the record *states* |
| `checked_at` | when the read happened | the action's timestamp, or the decision's |
| `outcome` | one of the five corpus outcomes | a boolean pass/fail |
| `reason` | why a check did not happen | a generic error string |

## One run, three reads

| # | Observer | Scope | Outcome | Reason / code | Read at | Accrual after this read |
|---|---|---|---|---|---|---|
| 1 | `caller:status-only` | `status:read` | `not_checked` | `access_refused` | 2026-11-19T16:40:00Z | 0 confirmed · 1 not checked |
| 2 | `auditor:files` | `files:orders/*` | `verified` | — | 2026-11-19T16:52:00Z | 1 confirmed · 1 not checked |
| 3 | `caller:status-only` | `status:read` | `not_checked` | `access_revoked` | 2026-11-19T17:05:00Z | 1 confirmed · 1 not checked |

Each row is an immutable event with its own `observation_id` (a digest over observer, scope, bytes, outcome and read time). The third read does not overwrite the first: `caller:status-only` is still **not checked / access_refused at 16:40** in the history, and **not checked / access_revoked at 17:05** in its latest state. Both are true. Neither is a failure of the receipt.

What the run supports, stated by the layer itself:

```
1 independent confirmation: auditor:files matched the bytes at 2026-11-19T16:52:00Z; caller:status-only did not check (access_revoked) at 2026-11-19T17:05:00Z · 1 execution
```

| Accrual field | Value |
|---|---|
| independent confirmations | 1 (`auditor:files`) |
| not checked, by observer | `caller:status-only` (access_revoked) |
| first read / first confirmation | 2026-11-19T16:40:00Z / 2026-11-19T16:52:00Z |
| composite | `verified` |
| contested | false |
| executions | 1 |

`executions: 1` is the whole point of the last row. The second and third reads added evidence about the same execution; neither replayed it.

`contested` is `false` here for a reason worth naming: the third read is an access refusal, and somebody who could not look does not contradict somebody who did. Only a later read that **looked at bytes and refused them** (`verification_failed`) sets `contested: true` — and even then the confirmation stays on the page instead of being quietly replaced by the newer row. A flag that fired on every partial-access run would train readers to ignore it.

## What the layer refuses, by name

Every refusal below is an attempted observation run against the same real subject at generation time, and the code is the layer's answer — not prose about the answer.

| Attempt | Refused with |
|---|---|
| not_checked with no reason | `NOT_CHECKED_WITHOUT_REASON` |
| not_checked with an invented reason | `UNKNOWN_REASON` |
| verified with no bytes read | `VERIFIED_WITHOUT_BYTES` |
| verified on a different digest | `VERIFIED_ON_DIFFERENT_BYTES` |
| an anonymous failure | `UNNAMED_FAILURE` |
| absent carrying bytes | `ABSENT_WITH_BYTES` |
| a read before the action | `READ_BEFORE_ACTION` |
| a reason on a finding | `REASON_ON_CHECKED` |
| an outcome this build does not know | `UNKNOWN_OUTCOME` |
| an observation with no observer | `MISSING_OBSERVER` |

Append order is enforced separately: a read appended after a later read is refused `OUT_OF_ORDER` — a backfilled observation cannot be made to look like evidence that existed before the decision it never informed.

## The five outcomes and the six reasons

The five outcomes, spelled exactly as the corpus spells them — an observation never invents a sixth:

- `verified`
- `verification_failed`
- `not_checked`
- `absent`
- `unresolvable_record`

`not_checked` reasons, frozen because the remedy differs:

| Reason | Remedy |
|---|---|
| `not_attempted` | nothing to fix on the record — nobody tried |
| `access_refused` | re-scope the caller, or read with another identity |
| `access_revoked` | the credential is gone; obtain access again |
| `outside_scope` | this verifier never claims that layer |
| `unsupported_family` | a build limitation, named as one |
| `schema_not_implemented` | upgrade the parser, then re-read |

## Boundary

- This layer observes what a verifier read. It never observes the world: matching bytes settle what the saved record says, not whether the purchase, delivery or transfer happened.
- No clock, no network, no keys. Every timestamp is supplied by the caller, which is what makes a replay of the same ledger byte-identical.
- `absent` is not a failure, `not_checked` is not a failure, and neither may be rendered as a refusal. Only `verification_failed` and `unresolvable_record` are findings about the record.
- The observers on this page are synthetic. The digest, the id and the recomputation are not.
